# v0.5.3 RAG 검색·답변 품질 개선

2026-11-02 사용자가 제공 지침을 모든 인증 업무기관과 현재 공개 시연 계정에도 검색·원문으로 제공하도록 승인했다. 지침 외부 AI 전송도 별도로 승인했다. 운영에서는 이 승인 범위에 맞춰 `RAG_LIBRARY_ENABLED=true`를 적용한다. 다른 설치의 기본값은 false다. 공유 승인은 법령 현행성 검증이나 실제 기관자료 운영 승인을 뜻하지 않는다.

## 변경

- 지침이 연결된 화면의 기본 검색 범위를 모두로 변경했다. 미설치 서비스는 프로그램 사용법으로 제한한다.
- 한국어 조사·금액 표기 정규화, 일상 표현과 업무 용어 확장, 본문/업무 주제/사용법 의도에 따른 순위를 추가했다. 프로그램 기능 질문은 앱 안내를 먼저 찾는다.
- 표지·변환 메타데이터보다 실제 본문을 우선하고, 신구조문 대비표의 개정안을 시행 규정으로 단정하지 않도록 했다. DESIGN은 명시적인 설계·개발 질문에서만 검색한다.
- 상위 구절과 같은 표의 인접 구절을 최대8개/본문 합계14,000자로 제한해 함께 보낸다. 실제 chunk ID·위치·MD 행을 그대로 유지한다. 원본 연결 여부와 기능 경로도 모델에 전달한다.
- 후속 질문은 명시적인 지시어가 있을 때 최근 질문 하나를 최대320자로 연결한다. 새 질문을 먼저 검색하고, ‘그룹’이나 짧은 새 질문만으로 이전 주제를 끌어오지 않는다.
- 계정·로그인 안내를 추가해 공개 프로그램 안내는10개다. 답변은 결론·순서·조건·예외와 실제 인용 근거를 중심으로 제시한다.

검색은 여전히 **SQLite FTS5/BM25 + 한국어 2글자 + 규칙 기반 순위**다. 새 임베딩 공급자나 벡터DB를 연결한 것은 아니다. 지침 인덱스·업무DB 스키마 변경은 없다.

## 검수

- 설치 `npm ci`: 알려진 npm 취약점0건.
- Node24 서버89개·TypeScript/Vite 빌드·Chrome E2E15개 통과. 기존 수량·증빙·기관 격리·파일 ACL 회귀검사 포함.
- 읽기 전용 실제 자료팩 `rag:check`:121문서/8,164구간 및 manifest SHA-256 일치. 공개 안내10개는 별도다.
- 동일 비교 질문15개: 검색 결과 없음4건→0건, 일반 업무질문에 DESIGN 혼입2건→0건. 이는 고정 평가 표본의 검색 결과이며 전체 질문 정확도를 뜻하지 않는다.
- 승인된 Hive `deepseek-ai/deepseek-v4.1-flash-1017`로 지침/서식/후속 질문12개와 프로그램 질문8개를 생성해 핵심 주장·수량·기간·예외·연결 원본을 근거와 대조했다. 모두 실제 반환 모델과 인용ID 검사를 통과했다.
- 첫 평가에서 표지 오선택과 원본 연결정보 누락을 발견해 수정하고20개를 재검사했다. 질의·답변·원문 대조 기록은 Git 제외 비공개 QA 경로에만 보관한다.


최종 반복에서 기존 거래 E2E가 이전과 같은 성공 알림만 기다려 세 번째 증빙 저장을 건너뛰는 문제를 발견했다. 각 단계의 POST 성공과 새 증빙 표시를 기다리도록 테스트를 보강했으며 서버의 증빙 검증은 유지했다. Mac 저장 공간 부족(ENOSPC)으로 중단된 실행은 성공으로 집계하지 않았다. 기존 파일을 삭제하지 않고 동일 소스·빌드·보강 테스트를512MB 임시 RAM 디스크 사본에서 실행해 최종 전체15개를 통과했다. 검사 산출물·합성 DB는 비공개 NAS 배포 기록에 보존했다.

최신 NAS 배포 SHA·백업/복원·화면 검수는 [NAS_DEPLOYMENT.md](NAS_DEPLOYMENT.md)의 최신 기록을 따른다.

## 남는 한계

자료팩은 제공판121문서이며, 원문/서식115개와 설계 참고6개다. 전부 현행성 미검증이다. 오래된 판본·신구조문·국가기관/서울교육청/사학기관 범위가 섞여 있고 원본 파일은3개만 연결됐다. 인용ID 검증은 모든 문장의 의미 정확성을 보증하지 않는다. 현행 법령 대조·대표 문의의 지속 평가가 필요하며, 새 자료는 승인 후 별도 버전으로 반입해야 한다. 금액·기한·공식 승인·원본 대장을 AI가 자동 확정하거나 수정하지 않는다.
