# v0.6 NAS 통합 마이그레이션·복구 계획

2026-11-03 확인: 최신 main의 v0.6은 조달/삽입사진 4개 테이블을 schema3에 추가하지만, 현재 NAS의 개선사항 버전도 schema3이며 feedback/feedback_attachments를 이미 사용한다. 따라서 main을 그대로 실행하면 신규 테이블 생성이 생략된다. 기존 기능을 보존한 통합 릴리스는 **schema4**를 사용한다.

허용 경로는 기존 schema1/2, 개선사항 schema3, 조달 schema3 → schema4다. 기존 테이블·행·인덱스·원본 자산 불변 트리거를 재생성하거나 삭제하지 않고, 없는 추가 테이블/인덱스만 한 트랜잭션으로 생성한다. schema4 재오픈은 멱등이며 더 높은 버전은 거부한다. 기존 NAS schema3에서는 조달/삽입사진4개 테이블만 추가되어21→25개 테이블이 된다.

실행 전 앱만 중지하고 업무DB+uploads 및 별도 rag-usage.sqlite를 일관되게 백업한다. 자료팩 버전 ZIP/manifest/파일 해시는 별도 보존한다. 백업을 존재하지 않는 새 DATA_DIR에 복원한 후 schema4로 열어 기존 모든 테이블의 전체 행 해시, 무결성/참조/첨부 해시, 로그인·원본 물품·개선사항·RAG를 검사한다. 실제 경로와 결과는 NAS_DEPLOYMENT.md에 기록한다.

롤백은 현행 schema4 DB·uploads·호출량을 먼저 보존한 뒤, 업데이트 전 schema3 백업을 **다른 새 경로**에 복원하여 검수하고 기존 ded598a 이미지/보호 환경설정과 연결한다. schema4 원본을 지우거나 그 파일에 구버전을 실행하지 않는다. schema4에서 새로 생성한 자료는 이전 백업에 없으므로 별도 보존·대조가 필요하다. 동일 NAS 백업만으로 별도 저장소 재해복구까지 완료했다고 보지 않는다.
