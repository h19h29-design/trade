# v0.9 NAS 통합·실제 사용자 OZD 검수

2026-11-04. 기준 main `01b4ecca51d09e20e26794df6ce02c0c62d83baf`. 중단된 v0.8 미커밋 수정은 codex/v08-nas-completion의97381f0에 보존한 뒤 새 통합 브랜치에서 이어갔다. NAS는 그동안522526d/v0.7.1을 유지했다. v0.9는 네이티브 변환을 사용하며 SDK·Viewer·변환 서버·새 브라우저를 설치하지 않았다. OZD_LEGACY_BRIDGE_FALLBACK 기본false와 기존 키·모델·사진AI·카카오 설정을 유지한다.

## 사용자 실제 파일

NAS에서 사용자가 보관한 `소요조회등록.ozd`(12,380바이트)를 해시 검증 후 별도 비공개 로컬 경로에 복사해 검사했다. 새 출력 경로에 `npm run ozd:convert`로 생성했고 기존 파일을 덮어쓰지 않았다. 결과는 **NATIVE_OZP3_DEMAND,1행·수량1개**, 외부 프로그램/변환/AI 호출0회다.

독립 Python PC1/struct/gzip 판독으로 저장된 원시 필드와 생성 XLSX의 **1행×9열 전체가 동일**함을 대조했다. 품명·목록/분류/식별번호·수량·취득일·취득단가·상태·신청수량을 보존한다. 보고서 화면 렌더링을 대조한 것은 아니며 인쇄 레이아웃/사진/스크립트 계산을 재현하지 않는다.

기존 로컬 소요조회물품목록.xlsx는20행/134개로 다른 완전 목록이다. 두 파일을 같은 목록이라고 가정하거나 행별로 같다고 주장하지 않았다. main 보고서의 공개 샘플15행/165개와 미확인13,505바이트 첨부파일을 이번12,380바이트 사용자 원본 검증으로 바꿔 보고하지 않는다. 실제 원본·원문 행·생성 XLSX·검수 DB/캡처는 Git·공개CI·외부 변환 사이트/AI에 넣지 않는다.

## 실제 웹 검수

비공개 로컬 DB에 이전 대기 원본을 복사해 업로드 이력→직접 변환 다시 시도→READY를 확인했다. 실제 파일 드래그→직접 변환 완료→변환 엑셀 받기→9셀 대조→미리보기→비공개1초안→실제 조달청 정확번호 후보·빈칸 입력→상세페이지를 조작했다.1440px/390px에서 가로 넘침이 없었다. 생성물 다운로드·원본 해시, 품명/번호/수량/취득일/단가/원본상태와DRAFT/UNVERIFIED/UNKNOWN을 확인했다. 실제0건 조회 후에도 원본 스냅샷·변환 XLSX 해시가 유지됐다.

네이티브 성공 파일에 외부 브릿지 호출은 없고, 기존 브릿지 테스트 더블은 명시적 legacy 회귀 검사에서만 사용한다. 미지원 버전·암호·손상은 일부 누락이나 양호 추정 없이 원본을 보존한다. 기존 게시·독립검토·기관격리·증빙·수량 관문은 유지한다. PC1 저작자 Alexandre Pukall(1991) 표시는 코드·문서·CLI 도움말·설정 화면에 유지했다.
