## 1. AI 물품검색: 실제 물품에 대한 구조화 RAG

검색은 인터넷 쇼핑 검색이 아니라 **사이트에 게시 승인된 다른 기관의 물품**을 대상으로 한다.
비공개 초안, 보류/종료 물품, 비활성 기관, 신청 가능 수량이 0인 물품과 자기 기관 물품은 모델에 보내기 전에 제외한다.

1. 문장·명시적 수량·지역·배송 조건을 받는다. 명시적 입력이 문장 수량보다 우선한다.
2. 기존 DeepSeek 연결과 신규 물품자료 전송 승인·사용자 동의가 있으면 품명·용도 동의어를 추출한다.
3. 최신 DB에서 권한 필터링한 문서(품명/규격/모델/설명/상태/수량/물품 사진 메타데이터)를 검색한다.
4. 한글 단어·동의어·부분일치 검색으로 후보 40개를 추린다. 수량/지역 등 구조화 기준으로 5개를 선정한다.
5. 포장정보와 확인된 출발 위치·배송지가 있으면 배송 계산을 수행한다. 배송 조건을 반영해 정렬하고 근거를 만든다.
6. AI는 선택된 **5개 이하 물품과 그 점수·근거만** 받아 비교 설명을 작성한다. 반환 물품ID·근거ID와 숫자를 검증한다.
7. 응답 직전에 공개 여부·기관 활성·버전·현재 가용수량을 다시 검사한다. 비공개 또는 예약 변경 후보는 제거한다.

이 버전은 별도 임베딩 서버/벡터 DB를 요구하지 않는 **실시간 구조화 RAG**다.
모든 문서를 외부로 전송하지 않는다. 기존 법령/지침 RAG와 물품 추천은 검색 범위와 권한이 다르므로 분리한다.
서버는 최대 5,000개 공개 문서를 후보 범위로 사용한다. 대규모 기관 운영에서는 전용 인덱스·캐시·부하검증이 후속 과제다.

### 점수 (0~100, `ai-core-1.0`)
| 항목 | 최대 | 의미 |
|---|---:|---|
| 용도 일치 | 45 | 품명·용도 단어 및 동의어의 일치 |
| 수량 충족 | 20 | 요청 수량 대비 현재 인계 가능한 수량 |
| 등록 상태 | 15 | 양호/사용감 분포. 실제 고장 여부를 AI가 판정하지 않음 |
| 선호 지역 | 10 | 같은 구 우선. 다른 구도 후보로 제시할 수 있음 |
| 정보 충실도 | 5 | 모델·규격·현물사진·운반 안내·포장정보 |
| 배송 조건 | 5 | 산정 가능 여부와 지정 배송예산 대비 범위 |

**제품 품질 확률·공식 등급·최저가 보장이 아닌 초기 설계의 참고지수**다.
세부 치수·호환성·성능·복잡한 부정조건은 모두 자동 확정하지 않는다. 검색 결과에 재확인 안내를 표시한다.
‘의자 말고 책상’과 같은 단순 제외 표현은 해당 품목을 제외한다.
양호+사용감 합계는 충분해도 단일 상태 묶음으로 부족하면 상태별 신청이 필요함을 표시한다.
부족 수량을 허용하지 않도록 설정할 수 있으며 원본 재고·예약을 수정하지 않는다.

### 배송
- 출발 위치: 물품 초안의 기관 상차 장소를 주소검색 후 담당자가 확인해 저장한다. 공개시 다른 기관에 보인다.
- 배송지: 검색자가 주소 후보 중 선택한다. 개인 주소·보안구역 정보를 넣지 않도록 안내한다.
- 크기/개당 무게가 없으면 배송비를 생성하지 않는다. 누락정보를 단점/확인사항으로 표시한다.
- 도로 경로 API가 연결되고 전송 동의가 있으면 해당 경로를 사용한다. 아니면 직선거리 × 1.3 추정임을 표시한다.
- 기존 배송 계산기를 재사용하며 수량, 차량 적재, 회차, 선택한 상하차·인력·계단 조건을 반영한다.
- `SHIPPING_RATE_CARD_JSON`이 없으면 기존 **시연용 가정 단가**다. 업체 확정견적·배차·결제는 하지 않는다.
- 도로 API는 승용차 기반이다. 화물차 통행제한·철거·설치·보험·통행료·현장 상황은 별도 확인해야 한다.

## 2. AI 물품등록

`OZD/XLSX/XLS 드래그 → 원본 보관 → 표 검증 → 비공개 초안 생성 → 조달조회 → AI 원문 보완`

- OZD는 기존 네이티브 parser를 사용한다. 지원형식/8MB/2,000행 제한, 원본 해시·변환결과 검사는 유지한다.
- 단일하고 확실한 품명·수량 매핑만 자동 등록한다. 여러 시트/모호한 열/잘못된 수량은 어느 물품도 만들지 않고 수동 확인 화면으로 넘긴다.
- 같은 원본/같은 매핑은 기존 confirmImport의 멱등 규칙을 사용한다. 개별 원본 행·취득정보·폐품 표기·자산/조달코드는 보존한다.
- 조달번호가 정확히 일치한 단일 후보에 한해 비어 있는 현물정보만 자동 입력한다. 코드가 원래부터 실제 물품과 다를 수 있어 현물 확인은 필수다.
- 품명 유사 후보는 저장하되 확정하지 않는다. 기존 조달정보 보완 UI에서 담당자가 선택할 수 있다.
- AI가 원문에 실제 존재하는 제조사·모델·설명 문구를 발췌하도록 하고 서버가 포함 여부를 검증한다. 원문에 없는 문자열은 반영하지 않는다.
- 호출은 한 물품씩 순차 처리하고 진행률·중단·재시도를 제공한다. 조회 실패·외부 API 미연결도 원본과 초안은 남는다.
- 분석 중 다른 사용자가 수정하면 낡은 결과를 덮어쓰지 않는다. 일시 오류는 같은 키로 재시도할 수 있다.
- **자동등록은 공개가 아니다.** 현물 상태·사진·불용결정 증빙·독립 검토가 완료돼야 다른 기관에 공개한다.
- 엑셀 삽입사진은 기존 현물·개인정보 확인 단계를 유지한다. 참고사진을 실제 상태 증빙으로 바꾸지 않는다.
- 등록 후 미리보기 만료가 돼도 `/api/ai-core/register/:id/status`와 정보 보완은 원본 기관 범위로 재개 가능하다.

## 3. AI 업무도우미
기존 대화 UI·접힌 참고자료·지침 코퍼스·원문 다운로드 권한·모델 설정은 유지한다.
프로그램 안내 지식에 AI 검색·점수·배송·자동 등록 설명 3개를 추가했다(프로그램 안내 총11개).
기존 비공개 지침 자료팩을 공개 Git에 복사하지 않았다. 지침의 외부 전송 승인과 최신성은 별도 확인한다.

## 연결 설정
| 설정 | 사용 |
|---|---|
| `DEEPSEEK_API_KEY`, `RAG_MODEL` | 기존 키/모델 재사용. 키는 서버에만 |
| `RAG_AI_ENABLED`, `RAG_EXTERNAL_APPROVED` | 기존 모델 기능·전송 승인 |
| `AI_CORE_ENABLED` | 미설정이면 RAG_AI_ENABLED 따름. 독립 비활성 가능 |
| `AI_CORE_DATA_APPROVED=true` | 새 물품·검색 데이터 외부전송의 별도 승인, 기본 꺼짐 |
| `AI_CORE_MODEL` | 선택사항. 미설정이면 RAG_MODEL 재사용 |
| `AI_CORE_DAILY_LIMIT` | 기관별 핵심AI 호출 제한, 기본100/일, 최대500 |
| `PROCUREMENT_ENABLED`, `DATA_GO_KR_SERVICE_KEY` | 기존 조달청 연동·활용신청 |
| `LOCATION_ENABLED`, `KAKAO_REST_API_KEY` | 주소 후보 조회 |
| `ROUTE_ENABLED`, `KAKAO_MOBILITY_REST_API_KEY` | 선택적 도로경로 |
| `SHIPPING_RATE_CARD_JSON` | 확인된 업체 단가가 있을 때만 실제 단가로 설정 |

AI가 없거나 미승인/오류면 등록정보 검색·원본 초안 저장은 계속 사용할 수 있다.
키를 사용자 브라우저에 반환하지 않고, 원문 대화본문 대신 해시/작업 종류/모델/동의만 감사기록에 남긴다.
물품 API 응답 내용/비밀키는 로그에 출력하지 않는다. 모든 쓰기 요청은 기존 인증/CSRF/역할검사를 따른다.

## 새 API
- GET `/api/ai-core/status`
- POST `/api/ai-core/search`
- GET `/api/ai-core/register/:id/status`
- POST `/api/ai-core/register/:id/start`
- POST `/api/ai-core/register/:id/enrich` (cursor, useAi, consent; 한 물품씩)

DB 스키마를 새로 만들거나 원본 DB를 초기화하지 않는다. 초안 JSON에 선택적 `pickupLocation`·`dimensionsConfirmed`만 추가했다.
다운그레이드 계획과 새 JSON 필드 보존 여부는 실제 운영 업데이트 전에 확인한다.
