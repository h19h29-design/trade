# 디자인 점검과 정리 기록 (v0.6, 2026-11-03)

담당: 디자인. 합성 시연 데이터로 데스크톱(1440px)과 휴대폰(390px)에서 12개 화면을 점검했습니다. 기능·서버 규칙은 바꾸지 않았습니다.

## 1. 점검에서 찾은 문제

| # | 문제 | 어디서 | 영향 |
|---|---|---|---|
| 1 | 한글이 단어 중간에서 줄바꿈 (찾아보/세요, 가능성으/로) | 휴대폰 전 화면 제목·설명 | 읽기 어렵고 완성도가 떨어져 보임 |
| 2 | 지정한 글꼴(Pretendard)이 실제로 불러와지지 않음 | 전 화면 | 업무용 PC에서 제목이 가늘게 보임. PC마다 모양이 다름 |
| 3 | 작은 회색 글자 대비 부족 (`#738078`, 13px) | 설명·카드 분류·메뉴 | 웹 접근성 기준(4.5:1) 미달 |
| 4 | 사이드바 메뉴 10개가 한 줄로 나열 | 데스크톱 | 자주 쓰는 메뉴와 도우미를 구분하기 어려움 |
| 5 | 상태 배지가 제목과 멀리 떨어진 오른쪽 끝에 있음 | 물품 상세 | 「나눔 중」을 놓치기 쉬움 |
| 6 | 「배송비 예상 계산」 버튼이 사진보다 먼저 나옴 | 물품 상세 | 주요 흐름(보고 → 신청) 앞에 부가 동작이 끼어듦 |
| 7 | 분류 칩이 화면 밖으로 잘리고 넘길 수 있다는 표시가 없음 | 휴대폰 물품 찾기 | 「교육·수업용품」 등을 못 찾음 |
| 8 | 정렬 칸만 혼자 다음 줄로 밀림 | 휴대폰 물품 찾기 | 필터 줄이 흐트러져 보임 |
| 9 | 하단 메뉴 글자 9px | 휴대폰 | 너무 작아 읽기 어려움 |
| 10 | 버튼에 마우스를 올리면 위로 뜸 | 전 화면 | 업무 화면에서 과한 움직임 |

## 3. 확인

- `npm test`: 73개 모두 통과.
- `npm run build`: 통과. 글꼴 조각 92개(각 40KB 안팎)는 화면에 나온 글자에 해당하는 것만 내려받습니다.
- e2e 11개 중 10개 통과. 남은 1개(`lifecycle.spec.ts` 원본 내보내기)는 이 점검 환경의 headless Chromium이 한글 다운로드 파일명을 「download」로 보고하는 문제로, 디자인 변경과 무관합니다(파일 내용 확인 전 단계에서 멈춤). 이 환경은 저장소가 고정한 Playwright 1.64 브라우저가 없어 설치된 Chromium으로 실행했습니다.
- 390px에서 물품 찾기·물품 상세 가로 넘침 없음.

## 4. 다음 제안 (팀 결정 필요)

1. **로고 교체:** `docs/design/` 시안 A·B 중 선택.
2. **물품 사진 비율:** 카드 사진을 4:3으로 고정하면 실제 현물사진이 섞였을 때 줄이 고르게 맞습니다.
3. **빈 화면 일러스트:** 「아직 신청한 물품이 없어요」 같은 빈 상태에 상자 그림과 다음 할 일 버튼 하나를 둡니다.
4. **상태 배지 색 체계:** 작성 중(회색) · 검토 대기(주황) · 나눔 중(초록) · 인계 완료(진초록) · 보류(빨강)를 한 표로 정해 모든 화면에서 같게 씁니다.
5. **발표용 화면:** 챌린지 시연을 위한 첫 화면(로그인 왼쪽)에 실제 숫자(등록 물품 수, 이어진 기관 수)를 크게 보여 주는 판.
