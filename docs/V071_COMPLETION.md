## 실제 분담과 통합

A는 document-import/ozd-converter/import-lifecycle/ozd-bridge 범위, B는 DropArea/ExcelImport/Assistant/chat-text/CSS 범위, C는 read-only 실접속·권한·원본·회귀 검수를 수행했다. A/C는 소스를 변경하지 않았고 B는 Assistant와 chat-text만 변경했다. 통합 담당이 충돌·스키마·테스트·배포를 처리했다. 전체 Playwright는 한 번에 하나만 실행했다.

## 실제 XLSX와 API

실제 사용자 파일은 별도 비공개 로컬 DB에서만 검사했다. 같은 파일의 두 로컬 사본이 바이트 동일함을 확인했다.20행·총134개·13종 목록번호이며 반복번호 중 취득정보가 다른4그룹의 개별 행도 유지한다. 원본20행의 전체 품명·번호·수량·취득일·취득단가·폐품, 원본 셀·BLOB·다운로드·파일 SHA를 전수 대조했다. 모두 DRAFT/UNVERIFIED/UNKNOWN·가능수량0으로 남고, 원본의 ‘폐품’을 양호나 공개 상태로 바꾸지 않는다. 원본에 없는 자산번호·사진은 생성하지 않는다.

실제 브라우저에서 DataTransfer 드래그→원본표→미리보기→20초안→실제 조달청 조회→정확번호 후보20건의 선택한 빈칸 입력→상세페이지를 확인했다. 빈칸 입력은 기본 미선택이며 원본·이미 작성된 제조사/모델·수량·상태·취득정보를 덮어쓰지 않는다. 실제0건·잘못된 입력 후에도 원본과 초안이 동일하다. 소유기관만 원본/미리보기/초안을 조회하고 다른기관404, 관리자403, 미인증401, CSRF403, 한글 다운로드명/no-store·확정멱등·이력을 확인했다.

인증오류·사용량제한·지연·통신실패·앱 일일한도는 별도 합성 격리 DB의5종 주입 검사다. 각 경우 개별 취득정보/폐품 두 행·초안·원본BLOB/다운로드 해시가 보존됐고 공급자 오류본문/키를 노출하지 않았다. 실제 제공기관 제한을 유발한 검사가 아니다. 실제 파일·원본 행·검수 DB/화면은 Git·Docker·NAS 공개 시연에 넣지 않는다.

## OZD

Desktop/Downloads/Documents/Developer 및 Spotlight에서 실제 사용자 OZD를 찾지 못했다. 표준 앱·지원 경로·설치 영수증에도 허가된 OZ/FORCS 내보내기 엔진을 확인하지 못했다. 따라서 실제 OZD→변환표→원문 행 대조와 자동변환은 미실행이다. 임의 실행파일/CLI옵션/ProgID를 만들거나 엔진을 설치하지 않았다.

브릿지는 내부 래퍼이며 실제 엔진이 아니다. 합성 입력으로 미인증401·엔진미설정/503·외부호출0, 원본보관/WAITING·재시도 비활성·물품0건, 동일OZD 수동XLSX 확인 조건과 원본 무결성·지연재개를 검사했다. 테스트 더블 변환을 실제 변환으로 세지 않는다. 실제 파일·허가 엔진/버전/라이선스·지원되는 내보내기 어댑터·비공개 호스트가 확보되고 품명/번호/수량 대조를 통과한 뒤만 활성화한다. 브릿지 전용 토큰은 이때 별도 비밀설정으로 관리한다.

## 대화창·화면
