# 물품이음 · 기관 간 물품공유 MVP

서울시교육청 공립학교·소속기관의 불용결정 물품을 **사진으로 찾고, 묶음·상태별 수량으로 신청하고, 양 기관 인계·증빙까지 추적**하는 웹앱입니다.

**합성 데이터 시연: [https://trade.h19h19.com](https://trade.h19h19.com)** — NAS 볼륨2에 저장하고 Cloudflare를 통해 제공합니다. 기관 운영 승인 전 시연이며 실제 행정자료는 입력하지 않습니다.

 > **v0.4.0 / 2026-11-01 NAS 반영 완료** — 실제 배포 소스는 `9712affa22991a4b021fccdb8e913b66d145a4f3`입니다. 기존 DB·계정·첨부를 보존하고 v1→v2 마이그레이션, 별도 경로 복원, 실제 HTTPS에서 등록·사진 품명·대량 상태·배송 계산을 검증했습니다. **등록·상태·수동 거리 계산은 키 없이 동작**하며 조달청·AI·주소/경로는 승인·서버 키 미확보로 미연결입니다. K-에듀파인·온비드 공식 처리는 수동입니다.

Node 24/macOS와 NAS Linux Docker에서 서버 **59개**, Chrome E2E **9개**, 빌드·의존성 검사(알려진 취약점 0건)를 통과했습니다. 공개 사이트의 1440px/390px 화면을 직접 조작하고 캡처를 열어 확인했습니다. 실제 비식별 에듀파인 파일은 제공되지 않아 XLSX/XLS 검수는 **합성 표**로 수행했습니다. 배송 단가는 **시연 가정이며 확정 견적이 아닙니다**. 백업·복원 경로와 남은 검수는 [NAS_DEPLOYMENT.md](docs/NAS_DEPLOYMENT.md), [V04_TEST_REPORT.md](docs/V04_TEST_REPORT.md)에 기록했습니다.

## 1. 가장 빠르게 실행하기

**Node.js 24.x**와 Git이 필요합니다. macOS / Windows PowerShell / Linux에서 동일합니다.

```sh
git clone https://github.com/h19h29-design/trade.git
cd trade
npm ci
npm run build
npm run demo
```

브라우저에서 **http://localhost:4310**을 엽니다. 터미널을 닫으면 서버가 종료됩니다. 이 명령은 배포하지 않으며 다른 운영 DB를 삭제하지 않습니다.

**2026-10-31 검수·배포 보강:** Node 24/macOS/Chrome에서 전체 거래 흐름을 검수하고 NAS Docker에서도 서버 40개 테스트와 빌드를 통과했습니다. 부분 첨부 실패·HEIC 안내·중복 CSV 열·백업복원을 보강하고 사용자 지정 도메인에 합성 시연을 배포했습니다. 최신 결과는 [TEST_REPORT.md](docs/TEST_REPORT.md), NAS 경로·복구 절차는 [NAS_DEPLOYMENT.md](docs/NAS_DEPLOYMENT.md), 외부 명세·필요 권한은 [INTEGRATION_READINESS.md](docs/INTEGRATION_READINESS.md)에 있습니다. 외부 API·AI는 승인·키 미확보로 미연결입니다.

macOS Documents/iCloud 경로에서 파일 읽기가 시간초과되거나 `dataless`로 표시되면 원본을 보존하고 동기화 폴더 밖의 작업 사본을 사용하세요. 이번 검수 사본은 `~/Developer/trade`입니다.

개발 중에는 `npm run dev` → **http://localhost:5173**. 기본 개발·시연 데이터는 `data/demo/`에 유지됩니다. 반복 실행해도 초기화하지 않습니다.

### 합성 시연 계정

**공통 비밀번호 `DemoTrade!2026`**. 로그인 화면의 ‘시연 계정 안내’에서 선택할 수도 있습니다. 이 비밀번호는 실제 업무 계정에 사용하면 안 됩니다.

| 기관(모두 가상) | 물품 담당자 | 업무 검토자 |
|---|---|---|
| 새빛초등학교 | `staff1@demo.local` | `review1@demo.local` |
| 늘봄중학교 | `staff2@demo.local` | `review2@demo.local` |
| 한결도서관 | `staff3@demo.local` | `review3@demo.local` |

운영관리자: `admin@demo.local`. 관리자는 기관·계정을 관리하지만 물품 게시·업무 승인을 대신하지 않습니다. 시연 이미지는 프로그램이 만든 **제품 일러스트**이며 실제 현물사진이 아닙니다. 모든 기관·물품·결정번호·증빙은 합성 데이터입니다.

## 2. 실제로 구현한 기능

| 기능 | 구현 내용 |
|---|---|
| 당근형 탐색 | 반응형 사진 카드, 제품명·모델 검색, 분류·지역·최소 수량 필터, 관심물품, 수량순 정렬 |
| 물품 등록 | 비공개 초안, 실제 제조사·모델·설명, 원본 대장 정보 분리, 현물사진·결재증빙 업로드 |
| 대량 수량 | 묶음 → 양호/사용감/수리검토/미확인 그룹. 상태별 합계 검증. 수리·미확인 그룹은 타 기관에서 숨김 |
| 게시 검토 | 결정번호·날짜·대상목록·사진·증빙 필수. 소속기관의 다른 검토자가 6가지 확인 후 게시. 작성자 본인 승인 금지 |
| 신청·배정 | 필요한 상태·수량·용도·희망일 신청, 중복 요청키 방지, 원자적 수량 예약, 반려·취소 |
| 원본 대장 | XLSX/XLS 직접 업로드·머리글 탐색·열 매핑·원자적 초안 등록. UTF-8/CP949 CSV도 유지. 직접 한 행 입력. 동일 원본 중복 감지, 원본 덮어쓰기 금지 |
| 자산 연결 | 원본 자산행을 묶음에 연결하고, 실제 인계 단계에서 이번 배정 수량만 연결 |
| 공식 업무 도우미 | 소요조회→양 기관 합의→인계·인수 승인→실물 확인→양 기관 대장 반영. 검토자가 본 기관 단계만 증빙 확인 |
| 인계·인수 | 보내는 기관과 받는 기관이 별도 확인. 수량 불일치 시 배정 재고를 계속 보류. 인계 전 저장매체 삭제 증빙 검사 |
| 업무 자료 | 거래 메모, 업무 확인서 Markdown 초안, 인쇄, 원본/물품 CSV, 온비드 준비 ZIP(사진+참고 내역) |
| 기관 운영 | 승인기관·계정 수동 발급, 담당자 중지·세션 폐기, 비밀번호 변경, 추가 전용 감사기록 |
| 제품 등록 보조 | 조달청 정확번호/품명 후보, 사진별 품명·용도, 승인된 AI 제안 선택 반영. 미설정은 차단 |
| 배송비 예상 | 포장 치수·중량·수량·거리·상하차 조건으로 계산, 단가/경로 근거와 범위 저장. 확정 견적·배차 아님 |

**‘증빙 확인 완료’는 담당자가 입력한 자료의 확인 완료이며, 공식 API로 확인된 행정완료가 아닙니다.** 공식 소요조회·합의·승인·대장 반영은 허가된 공식 시스템에서 별도로 진행해야 합니다.

## 3. 시연 순서

1. `staff2`로 로그인 → ‘강당 의자’ 검색 → 양호 3개 받기 신청.
2. 로그아웃 후 `staff1` → 신청·인계내역 → 들어온 신청 → 수량 예비 배정.
3. 보내는 기관 `review1`, 받는 기관 `review2`가 각각 자기 기관 증빙을 첨부하고 공식 단계 근거를 기록합니다. **실제 문서 대신 합성 테스트 PDF/이미지를 사용합니다.**
4. `staff1`에서 해당 거래의 연결 자산에 3개 배분 → 모든 선행 증빙 확인 후 실물 인계.
5. `staff2`에서 인수 수량을 기록합니다. 2개를 기록하면 불일치, 3개를 기록하면 인수 확인 상태가 됩니다.
6. `review1`과 `review2`가 각자 대장 반영 증빙을 기록 → 검토자가 모든 증빙 확인 완료.

신규 게시 시연은 `staff1`에서 물품 올리기 → 초안 저장 → 사진·증빙 첨부 → 저장 → 상세의 게시 검토 요청 → `review1`이 검토합니다.

자세한 시나리오: [docs/DEMO_AND_TESTS.md](docs/DEMO_AND_TESTS.md)

## 4. 외부 연결 없이 새 환경 구성

**실제 기관 자료는 운영기관 승인·보안 검토 전 입력하지 마세요.** 아래는 데모 계정 없이 로컬 설정을 검토하는 방법입니다.

```sh
# PowerShell
Copy-Item .env.example .env
# macOS/Linux에서는: cp .env.example .env
npm run setup
npm run build
npm start
```

`setup`은 최초 관리자 이메일과 기관정보를 질문하고 임의 생성한 비밀번호를 터미널에 한 번 표시합니다. 기존 계정이 있으면 초기화하지 않고 중단합니다. 로그인 후 비밀번호를 변경하고, 기관 소속·담당자 지정 근거를 확인하여 **물품 담당자와 별도 업무 검토자**를 만듭니다.

기본 저장 위치: `DATA_DIR/trade.sqlite`, `DATA_DIR/uploads/`. `.env`, DB, 업로드 파일, 백업은 Git에서 제외됩니다. 데모는 기본 `data/demo/`, 일반 실행은 기본 `data/`를 사용합니다.

## 5. 테스트·빌드

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

브라우저 다운로드가 어려운 Mac에 Chrome이 설치되어 있으면 `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`로 실행할 수 있습니다. E2E는 시연 포트 4310을 재사용하지 않고 **4311 + 실행별 새 `data/e2e-*`**를 사용합니다. 4311이 사용 중이면 `E2E_PORT=4312`처럼 지정하세요. 기존 DB나 이전 검수 데이터는 삭제하지 않습니다.

Linux에서 브라우저 시스템 패키지가 없으면 `npx playwright install --with-deps chromium`을 사용합니다.

GitHub Actions는 Node 24에서 도메인·동시 예약·HTTP 보안 테스트 → TypeScript 검사/프로덕션 빌드 → Chromium E2E/모바일 폭 테스트를 실행합니다. 결과·스크린샷은 **Actions → Trade CI → Artifacts**의 `trade-qa-*`에, 성공한 소스+빌드는 `trade-mvp-source-and-build`에 저장합니다. 테스트 통과 여부는 각 커밋의 Actions 결과가 기준입니다.

## 6. 백업·배포

`npm run backup`은 타임스탬프 디렉터리에 SQLite 백업·첨부·SHA-256 검증표를 생성하고 DB 무결성과 첨부 해시를 검사합니다. 원본 DB가 없으면 빈 DB를 만들지 않고 실패합니다. **DB와 첨부의 일관성을 위해 앱을 중지한 뒤 실행하세요.** `npm run restore -- <백업경로> <존재하지_않는_새_DATA_DIR>`은 검증 후 새 경로로만 복원합니다. 기존 경로는 덮어쓰지 않습니다. 상세 절차는 [운영 문서](docs/OPERATIONS.md)를 따릅니다.

승인된 배포 설정을 준비한 뒤 `npm run preflight`로 Node·HTTPS 출처·Secure 쿠키·명시적 저장경로·데모 계정 분리·DB/첨부 무결성을 검사하세요. 이 검사는 읽기 전용이며 실제 TLS 종단, 영속 볼륨, 별도 저장소 백업, 기관 보안·배포 승인은 따로 확인해야 합니다.

사용자가 지정한 **NAS 볼륨2 + Cloudflare + `trade.h19h19.com`** 배포를 완료했습니다. 기존 NAS 터널과 서비스를 보존하는 별도 Compose 구성, 실제 데이터·백업 경로와 재기동·복원 결과는 [NAS_DEPLOYMENT.md](docs/NAS_DEPLOYMENT.md)에 있습니다. 기관 운영 승인이 없는 동안은 별도 합성 시연 DB를 사용합니다.

본 앱은 **단일 Node 서버 + 영속 디스크**가 필요합니다. 정적 사이트만 배포하거나 SQLite를 임시 파일시스템에 두면 안 됩니다. Docker 구성을 포함하지만, 기본은 로컬 검토용입니다. 원격 접속은 승인된 HTTPS 인프라와 보안 설정을 갖춘 뒤 진행하세요. 개인 NAS나 무료 클라우드에 실제 교육기관 자료를 먼저 넣는 방식은 권장하지 않습니다.

## 8. 중요 한계

현재는 **3일 내 검토·시연을 위한 MVP**입니다. 공식 기관 인증/SSO, 전체 법령 정책엔진, 악성코드 검사 서비스, 자동 개인정보 마스킹, 공식 서식 HWP/XLSX 반출 호환, 개별 QR/RFID, 자동 알림/푸시, 공식 시스템 API는 구현 또는 연결하지 않았습니다. XLSX/XLS 입력과 제품·AI 보조 어댑터는 v0.4에 구현됐으나 실제 기관 양식·외부 공급자·참고사진 이용권 검수는 남아 있습니다. 반송 후 재고 재편입과 복잡한 부분 종결도 별도 구현 대상입니다. 상세 내용은 범위 문서를 확인하세요.

공개 저장소에는 실제 기관 문서·자산대장·사용자 개인정보·API 비밀키를 올리지 않습니다.
